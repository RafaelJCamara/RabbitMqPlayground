# M1 (MVP) implementation plan — RabbitMQ Playground

## Context

ADRs 0001–0017 (in `docs/adr/`) settle the scope, design and process. ADR-0003 defines **M1 · Build & route** as the
first shippable milestone. This plan turns the M1 checklist into an architecture and 13 ordered vertical slices
(S0–S12), each pushed to `main` behind feature flags until it's finished ([ADR-0004](../adr/0004-trunk-based-development-on-main.md)).

### Decisions from this planning round (user)
- **Workspace layout:** the Angular/npm workspace lives in **`web/`**. The repo root keeps `docs/`, `.github/`,
  `LICENSE` and the README. If a .NET API ever arrives, it goes in `api/`.
- **Tracking:** a GitHub parent issue **"M1 · Build & route (MVP)"** with **one sub-issue per slice**, labelled `M1`.
  The GitHub tools here can't create milestones; if the user creates an `M1` milestone later, I attach the issues to it.
- **Workflow after approval:** build slice by slice, pushing each to `main`. Pause only for decisions or problems.
- **Licence:** **MIT**.
- **Name:** keep **"RabbitMQ Playground"**, with a "not affiliated with Broadcom" disclaimer, and no logo.
  The name sits in one constant; revisit it before any public promotion.

### New ADRs, written in S0 (per ADR-0001)
- **ADR-0018:** workspace layout and dependency rules (§1).
- **ADR-0019:** undo through immutable document snapshots. It supersedes the "produces patches" clause of
  ADR-0011's "One command layer" (§2.3).
- **ADR-0020:** MIT licence.
- **Fixture-driven corrections:** when a conformance fixture contradicts a rule in ADR-0008 or ADR-0009, a superseding
  ADR lands in the same push.

## 2. Key interfaces (sketches)

### 2.1 Document model (domain; header types in engine)
```ts
type HeaderValue = {t:'string';v:string}|{t:'integer';v:number}|{t:'float';v:number}|{t:'boolean';v:boolean};
type HeaderCondition = HeaderValue | {t:'exists'};            // always tagged: JSON can't tell 1 from 1.0
interface CanvasDocument {                                     // immutable; the unit of undo
  schemaVersion: 1; rabbitmqBaseline: '4.3'; vhost: string;
  exchanges: Rec<{name; type; durable; autoDelete; internal}>;  queues: Rec<{name; serverNamed; durable}>;
  bindings: Rec<{source: Id; dest: {kind:'queue'|'exchange'; id}; key; headers?: {xMatch: XMatch|null; args: {key; value: HeaderCondition}[]}}>;
  producers: Rec<{name; target: {kind:'exchange'|'queue'; id}|null; message: {payload; key; headers: {key; value: HeaderValue}[]}; burst; interval: {everyMs; on}}>;
  consumers: Rec<{name; queues: Id[]; ack:'auto'|'manual'; prefetch /*0=∞*/; processingMs}>;
  layout: {nodes: Rec<{x;y}>; labels: Rec<{at:number}>};  settings: {showDefaultExchange; seed; timing};
}
```
Ids are stable and names are attributes, so a rename keeps every reference. Names are unique within a kind; commands accept the `queue:x` / `exchange:x` qualifiers.

### 2.2 Engine (pure, deterministic; ADR-0007/0008)
```ts
createEngine({seed, timing:{publishMs, brokerMs, deliverMs}}): Engine
interface Engine { dispatch(c: EngineCommand): {ok:true; events} | {ok:false; code:403|404|406; text};
  advanceTo(t): EngineEvent[]; step(): EngineEvent[]; now(); view(): RuntimeView; snapshot(); restore(s); }
// EngineCommand: exchange/queue declare|delete|purge, bind/unbind, channel.open|close, basic.consume|cancel|ack|publish,
//                producer.set|remove, sim.clearMessages|resetCounters  (also the conformance scenario vocabulary)
// events: published, routed{queues,paths,trace}, unroutable{trace}, enqueued, delivered{redelivered}, acked, requeued,
//         consumer.cancelled, channel.closed, refused
route(topology, {exchange,key,headers}) → {queues, paths, trace}      // pure; powers Why?/what-if
explainMiss(...); topicSamples(pattern)
```

**Dispatch** follows RabbitMQ's active-consumer FIFO:
- deliver to the consumer at the head, then re-append it at the tail;
- a blocked consumer rejoins at the tail;
- prefetch is counted per consumer tag;
- `basic.cancel` keeps unacked messages; closing the channel requeues them with `redelivered=true`.

### 2.3 Command layer (domain; ADR-0011, ADR-0019)
```ts
interface CommandSpec<C> { type; scope:'document'|'runtime'|'app'; syntax; summary; examples;
  parse(tokens, doc); complete(tokens, doc); format(c, doc) /* equivalent command */; apply?(doc, c): Result<CanvasDocument> }
class History { push(prev); undo(cur); redo(cur) }      // document references, cap 200: O(1) undo, no inverses
reconcile(prev, next): EngineCommand[]                   // one path for do / undo / redo / load / clear
```
- **Verbs:** ADR-0011's set, plus `add`, `set`, `move`, `layout`, `undo`, `redo`, `purge`, `pause`, `resume`, `play`,
  `step`, `speed`, `clear messages`, `reset counters` and `export`.
- **Exists conditions** are written `exists(key)`.
- **Drag-to-create** is one `batch` command, so it is one undo step.
- **Undo restores the design, not the simulation.** A toast says so.

### 2.4 Foblex adapter (only `projects/app/src/app/canvas/flow/**`; ADR-0016/0017)
```ts
FlowCanvas { model = input<CanvasVm>(); rules = input<LinkRules>(); intent = output<CanvasIntent>() }   // owns the @for loops
LinkRules { allowedTargets(source): Id[]; explain(source, target): string }
CanvasIntent = link{via:'drag'|'click'|'keyboard'} | link-invalid | link-to-empty{at} | move | delete | select | context-menu | drop-new
FlowViewport { live(); set(t); fit(); zoom(); reveal(id); select(); edgePath(id); drawn: Signal<Set<Id>>; toFlow(p); announce(msg) }
```

Hidden inside the adapter:
- **Live transform.** `transform.position + scaledPosition`, scaled by `scale`.
- **Allow-list arming.** The allowed targets are filled on a capture-phase `pointerdown` and on `fSelectionChange`, with
  the sentinel `['∅']` meaning "none".
- **Drop classification.** An `elementsFromPoint` hit test tells an invalid drop from a drop on empty canvas.
- **Drawn edges.** A `MutationObserver` on path `d` attributes reports which edges have been drawn.
- **Keyboard guard.** A capture guard stops Ctrl/Cmd+M from picking up a node.
- **Our wording.** Our own aria-labels and message catalogue.
- **Configuration.** `provideFFlow(withA11y({keys:{connect:['l'],grab:['m']}}), withConnectionFlow('click'))`.

`@foblex/flow` is pinned to an exact version. Counters are per-node signals, so a running simulation never re-checks
the large `@for` template. Patterns are ported from the ADR-0016 spike.

### 2.5 Persistence & sharing (ADR-0012/0013/0014)
- **`CanvasRepository`:** an `idb` implementation and an in-memory one. It supports soft-delete tombstones for the
  Undo toasts, a meta store, and `estimate()`.
- **Loading.** Migrations are append-only. `loadCanvas(raw)` runs version check → migrations → strict zod with size caps →
  reference check. A fixture is required per schema version.
- **Share codec.** `'v1.' + base64url(deflate-raw(canonical JSON))`, built on native `CompressionStream`.
  - Input is capped at 256k characters and the inflated size at 2 MB, counted while streaming.
  - Decoding goes through the same `loadCanvas`.
  - URL form: `<base>/#c=…`. Above 8k characters the app warns and offers a file download.
- **`definitions.json` export:**
  - floats are written as `1.0`;
  - bindings with *exists* conditions are skipped and listed;
  - simulator-only elements and server-named queues are listed.

## 4. CI/CD
**`ci.yml`** runs on push to `main`, on PRs from forks and Dependabot, and on dispatch, with
`defaults.run.working-directory: web` and Node from `.nvmrc`.
1. **verify:**
   - `npm ci`, then lint, `format:check`, typecheck;
   - library tests with coverage (engine 95, domain 95, persistence 85) and app tests with coverage (85);
   - `docs:check`;
   - production build with budgets as errors, `--base-href /RabbitMqPlayground/`, and `404.html` for deep links.
2. **e2e:** Playwright Chromium (cached) and axe against the production `dist`, with no retries and traces on failure.
3. **bench:** results go to the job summary; it fails only on gross limits.
4. **deploy** (`main` only): `deploy-pages`, then a smoke test against the live URL.
   - **One-time manual step:** Settings → Pages → Source = GitHub Actions.

**`nightly.yml`** runs on a schedule and on dispatch, in `verify` or `record` mode:
- **Conformance** runs against `rabbitmq:4.3-management`. Any drift fails the job, uploads a diff, and opens or updates a
  `conformance-drift` issue. Recorded fixtures are reviewed and committed by a person.
- **Fuzz:** the property suites run with a random seed and 5,000 runs. A failing seed becomes a regression case.

**Pre-push** (lefthook, in parallel): lint, format check, typecheck, both coverage runs, and a development build.
The target is under 2 minutes.

**Locally (this container):**
- Node 24 is put on the PATH by the SessionStart hook.
- `PW_CHROMIUM_PATH` points at `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`; CI is the authority.
- Docker is absent, so the live conformance run skips locally and is required in CI.

## 5. Conformance harness (M1 scope)
- **Fixture format.** Each fixture holds the inputs and the outputs the broker produced:
  `web/fixtures/conformance/4.3/{routing,delivery}/*.json`, plus a `manifest.json` with the image digest, server
  version, generator SHA and counts.
- **Routing cases:**
  - direct, case-sensitive; fanout;
  - topic edge cases: `""`, `#`, `*`, `a.#`, `a.#.b`, `a..b`, `a*`, 255-byte keys;
  - headers: the four modes plus x-match omitted; values `"1"`, `1`, `1.0`, `true`; `x-` keys; exists; nothing counted;
  - default exchange; E2E chains, diamonds, cycles, self-binding; unroutable;
  - seeded random topologies.
- **Delivery cases:**
  - round-robin; unequal prefetch; prefetch 0; auto-ack ignoring prefetch;
  - re-append order; a consumer joining late;
  - cancel keeping unacked messages; close requeuing with `redelivered`;
  - #10 and #18.
  Per-consumer order is compared, because interleaving across consumers isn't observable on a real broker.
- **Runner** (`@testcontainers/rabbitmq` + amqplib):
  - each case gets its own vhost;
  - typed headers are sent as amqplib tagged values, and exists is sent as `null` (encoded as void);
  - messages are published with `mandatory` and confirms, then queues are drained with `basic.get`;
  - waits are count-based.
- **Engine checks without Docker.** Engine specs load the committed fixtures and replay them through `route()` and
  `createEngine`, on every push.
- **Open questions the fixtures settle:**
  - Does `1` equal `1.0`? Do integer widths or booleans matter?
  - How many words does `""` have?
  - What is the requeue and unblock order?

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Foblex workarounds break on upgrade | Exact pin; Foblex imports only in the adapter; contract suite gates upgrades; ask upstream for a viewport signal and a validator callback |
| M1 is large | Feature-flagged slices, parallel tracks after S5, the timeboxes above |
| Fidelity surprises | Routing fixtures before any UI (S1). CC/BCC sender-selected distribution is outside ADR-0008 coverage: follow up with a lint or an ADR |
| Flaky nightly | Count-based waits, per-consumer comparison, no retries |
| Performance (39 fps with the overlay in the spike) | Per-node counter signals; overlay outside change detection; ×N grouping; lazy editor chunk; budgets; CI check that 200/500 is drawn in under 3 s; real-hardware check in S12 |
| Accessibility regressions | axe on every push in both themes; keyboard-only journey; manual screen-reader pass |
| Compatibility contracts (grammar, links, files) | Golden command texts, golden v1 links, schema fixtures per version |
| Storage eviction (Safari's 7-day rule) | `persist()`, backup prompts, file export |
| Pages base path | `--base-href`, `404.html`, E2E served under the same base path, post-deploy smoke |
| Trademark ("RabbitMQ" is Broadcom's) | Disclaimer, no logo, name in one constant; revisit before public promotion |
