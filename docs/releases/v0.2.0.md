# RabbitMQ Playground v0.2.0: Import, quieter home, and Docker

*Released on 2026-10-20, on the tag `v0.2.0`.*

A browser-based, explanation-first RabbitMQ simulator for learning, teaching and designing topologies. This release brings a topology from a real broker onto a canvas, lets the notes of the home be put away, and runs the whole playground on your own machine with one command.

*Not affiliated with, endorsed by or sponsored by Broadcom Inc. or the RabbitMQ project.*

**Try it:** <https://www.rabbitmqplayground.com/>, or `docker compose up -d` in a clone of the repository.

## What is new

- **Import a `definitions.json` into a canvas** ([ADR-0111](../adr/0111-a-definitions-file-is-imported-into-the-open-canvas-and-replaces-what-it-has-in-one-change-that-undo-takes-back.md)). "Import…" beside "Export…" in the top bar reads a file that RabbitMQ exported (from the management UI or `rabbitmqctl export_definitions`). A dialog says what the canvas will have, asks which vhost when the file has several, says that it replaces what is on the canvas, and lists what it leaves out or changes and why: users, permissions, policies, the other vhosts, the exchanges that a broker makes itself, exchange types of plugins, queue types and arguments that the simulator does not model. The import is one change: **Undo**, from its notice or with Ctrl/Cmd+Z, gives the canvas back. A header value written `1.0` stays a float and `1` an integer, as on the broker. A file that this app exported imports back to the same file.
- **`set canvas vhost=…`** in the command bar sets the vhost of a canvas, which the export then offers first. The import uses it.
- **The notes of the home can be closed** ([ADR-0110](../adr/0110-the-notes-of-the-home-can-be-closed-and-stay-closed-in-that-browser.md)). The note that the canvases take up space in the browser, the note that the browser did not promise to keep them, the warning about the room and the note that nothing is kept after the tab is closed each have a close button, and stay closed in that browser. Closing the warning at 80% does not hide the one at 95%.
- **Run it with Docker** ([ADR-0112](../adr/0112-docker-compose-up-at-the-root-builds-the-pages-build-and-serves-it-with-nginx-as-a-user-that-is-not-root.md)). `docker compose up -d` at the root of the repository builds the same files that the live site serves and serves them with nginx at <http://localhost:8080>, as a user that is not root, read-only, with no capabilities. Behind nginx the page also refuses to be framed, which GitHub Pages could not do. Your canvases stay in your browser, so stopping or rebuilding the container loses nothing.
- **Two buttons of the inspector have names that say what they show** (WCAG 2.5.3, Label in Name). "Link to…" is named "Link to… from exchange orders", and "Delete this binding" is named "Delete this binding, 1 of 2", where they were "Link exchange orders to…" and "Delete binding 1 of 2". axe 4.14 checks the rule, and the tag is on the commit that passes it.
- **Dependencies are up to date** as of the tag: Playwright and axe-core/playwright 4.14, ESLint 10.13, zod 4.6.7, postcss 8.5.30, lefthook 2.2.2, fake-indexeddb 6.2.6 and @testing-library/angular 19.6.

## What is not in it

Opening a definitions file as a new canvas from the home (the import replaces the open one), quorum queues and streams (they are imported as classic queues, and said to be), an image published to a registry, and everything that v0.1.0 listed for the milestones after it ([ADR-0003](../adr/0003-roadmap-and-milestones.md)).

## Compatibility

- The canvas file and the backup are still **schema v1**, and a share link is still **`v1.`**: what v0.1.0 made opens in v0.2.0, and the other way round.
- The browser keeps one more small value, the notes that were closed (`dismissedNotes`). v0.1.0 ignores it.

## What was checked, and what was not

Checked by machines on the pull request of this release: lint, format, types, about 6,300 tests of the libraries and tools (the coverage gates hold), about 3,000 tests of the app, 858 end-to-end tests in Chromium including axe on every screen in both themes (with the two states of the import dialog added to [docs/accessibility.md](../accessibility.md)), and the smoke test of the live site run against the container. The properties of the import (the export of any canvas imports back to the same file; a file damaged anywhere is refused in words and never throws) passed at 5,000 runs with five seeds. The broker's files that the import is tested with were exported by RabbitMQ 4.3.6 itself.

**Not checked, and so not claimed:** a manual pass with NVDA or VoiceOver, still a task for later ([#20](https://github.com/RafaelJCamara/RabbitMqPlayground/issues/20)); the frame rate on a mid-range laptop ([#21](https://github.com/RafaelJCamara/RabbitMqPlayground/issues/21)); how long an import of the largest canvas takes on such a laptop; the container on a machine with an ARM processor.

## Known limits

- An import replaces the canvas. Undo is held in memory by the editor, so after a reload the old canvas is gone; duplicate a canvas first to keep both.
- The line of an import in the log of equivalent commands has every command of it, which is long for a large file.
- A canvas made in the container's playground is kept by the browser for `localhost:8080`, which is not the live site: move it as a file or a backup.
- The limits of v0.1.0 stand, except that the container can forbid framing.
