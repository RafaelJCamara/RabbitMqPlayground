# routing/unbinding-an-exchange-from-an-exchange
# An exchange-to-exchange binding is taken away by an unbind, and then nothing is routed through it (ADR-0051)
#
# What a learner is told about each publish of this scenario, as `explanationText` writes it (ADR-0060).
# The lines that start `broker:` are what RabbitMQ 4.3 recorded. A golden file is never regenerated to make a failure go away.
# The first 8 publishes are written in full, and the others as their four lines: the spec holds all of them to the broker.

## publish 1 of 2: "m1" (step 6)
broker: reached inbox
message: published to "front" with key "k"
outcome: routed
reached: inbox
summary: Reached inbox.

exchange front (direct): front is a direct exchange, and the message was published to it. 1 of its 1 binding matched.
  ✓ front -> exchange back ("k") [key matches]
    The key "k" is the binding key, letter for letter. The message goes on to the exchange back.
    exchange back (fanout): back is a fanout exchange, and the message came to it from front. 1 of its 1 binding matched.
      ✓ back -> queue inbox (any key) [fanout: always matches]
        A fanout exchange sends every message to every queue and exchange that is bound to it, whatever the key. The queue inbox gets its first copy.

queue inbox: reached through ✓ front -> exchange back ("k") [key matches] ; ✓ back -> queue inbox (any key) [fanout: always matches]

## publish 2 of 2: "m2" (step 8)
broker: returned, no queue got it
message: published to "front" with key "k"
outcome: unroutable
reached: nothing
summary: No queue got it: it reached front, which has no bindings.

exchange front (direct): front is a direct exchange, and the message was published to it. It has no bindings.

queue inbox: not reached
  The queue inbox did not get the message.
  - back is bound to queue inbox (any key), but the message never reached back.
    - Nothing is bound to the exchange back, so nothing leads into it and the message cannot reach it.
